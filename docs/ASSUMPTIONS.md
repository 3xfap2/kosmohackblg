# Допущения команды

Это **не условия организатора**, а настройки и допущения нашего решения. Каждое — с причиной
и способом проверки. Значения меняются только с записью здесь и в `CRITERIA.md`.

| ID | Допущение | Значение | Почему | Как проверяем | Владелец |
|---|---|---|---|---|---|
| A1 | Окно планирования CP-SAT | 48 шагов (4 ч) | Максимальное окно задания — 29 шагов; орбита ≈ 19 шагов (12 свет + 7 тень) — окно покрывает ~2,5 витка | Чувствительность 24/36/48/72 — `results/research.json` (P02, приоритет) | Codex |
| A2 | Период плановой перестройки | каждые 6 шагов + при событии, смене цели, отказе действия | Баланс времени расчёта и свежести плана | Сравнение 3/6/12 — `results/research.json` | Codex |
| A3 | Ценность остатка энергии в конце окна | 0,5 $/Вт·ч | Без неё окно разряжает батареи перед своей границей | Чувствительность 0 / 0,25 / 0,5 / 1 — `results/research.json` | Codex |
| A4 | Вес задания приоритета 3 в режиме «Приоритетное обслуживание» | 100 000 $ за задание (взвешенная эвристика, не гарантия лексикографического порядка для произвольного ввода) | Постановка: «основная цель — P3 в срок; при сопоставимом выполнении — выручка» | Сравнение целей на P02/P03 | Codex |
| A5 | Прогноз температуры внутри планировщика | по траектории плана goal-greedy | Прогноз согласован с AddHint. При изменении действий CP-SAT температура может отличаться. Гарантии консервативности нет: нагрев влияет на зарядку. Итог, проверка плана и Admission — через модель организаторов. Ещё ограничение окна: CP-SAT не планирует задания, которые нельзя завершить внутри 48 шагов (частичная работа с переходом в следующее окно не моделируется); такие задания может начать эвристика | tests/test_review1.py; контрпример в tests/test_planner.py; plan_rejections в результатах | Codex |
| A6 | Детерминированность решателя | seed=7, workers=1, max_deterministic_time=0.5, linearization_level=0, cp_model_presolve=False, AddHint по goal-greedy, OR-Tools 9.11.4210 | Лимит — единицы работы решателя, не секунды настенных часов; API продолжает расчёт кусками по бюджету | Двойной прогон полных результатов и replay; время отдельно в results/timings.json | Codex |

| A7 | Защита от слабого решения CP-SAT | Сравниваем план с goal-greedy через официальную Session на одном окне; при не худшей оценке выбираем эвристику (P3, затем выручка / только выручка). Запасной режим также goal-greedy | EDF остаётся отдельной базой сравнения; поиск может вернуть слабый план | baseline_guard_solves и cpsat_selected_solves; гарантия только для текущего окна, не всей смены | Codex |
| A8 | Сопоставимость ветвей | Одинаковые исходные данные, состояние на развилке, события и конечный шаг; допуск денежных показателей 0.000001 $ | Точность официальной сводки — 6 знаков; P3 сравнивается как целое | tests/test_service.py | Codex |

| A10 | Отсечка безнадёжных заданий | не брать, если до срока шагов или шагов с контактом (вне известной недоступности исполнителей) меньше, чем остаток работы | Незавершённая работа занимает аппарат, но не приносит дохода | P02: все потери P3 доказуемые (tests/test_greedy.py) | Codex |
